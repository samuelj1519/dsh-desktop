# 架构设计

[English](design.md) | [简体中文](design.zh-CN.md)

## 范围与模块

客户端是独立的 Electron 外壳，承载所选本机 dsh 服务的 Web UI。不复制 dsh RPC、模型执行、会话或工具授权逻辑。dsh runtime 需单独安装；明确选择其 Node 程序、JavaScript CLI、Home 和工作目录。

| 模块 | 职责 |
| --- | --- |
| `src/contracts.ts` | 共享后端接口和不可变连接状态投影。 |
| `src/backend.ts` | 就绪检查、连接状态、进程所有权、诊断和清理。 |
| `src/config.ts` | 严格设置校验、路径发现、启动参数和持久化。 |
| `src/main.ts` | 窗口、受信 IPC、导航规则、菜单和退出协调。 |
| `src/preload.cts` | 本地设置页的窄 CommonJS 桥。 |
| `src/renderer.ts`、`ui/` | 连接表单、传输状态、错误和重试操作。 |

## 连接状态与所有权

`BackendManager` 实现 `DesktopBackend`。调用方使用 `startOwned`、`attach`、`disconnect` 和 `dispose`，并订阅不可变状态。阶段为 `idle`、`starting`、`connected`、`stopping` 和 `error`；所有权为 `owned`、`external` 或 `null`。连接状态仅表示传输可用性，不表示模型或任务成功。

自有启动使用选定的程序和 CLI：

```text
node /absolute/path/to/launcher.js web --host 127.0.0.1 --port 0 --no-open
```

启动必须收到完整的 `dsh web: http://127.0.0.1:<port>` 就绪行，端口不得为零；随后对服务根地址执行 HTTP GET 并成功。就绪地址无效、HTTP 错误、超时或取消都会导致启动失败。持续读取两个输出流，只保留有限长度的诊断。退出码、信号、超时和强制停止分别记录；超时进程即使以零退出码结束，仍属于启动失败。

取消时先撤销当前操作，再向进程发信号；阻止晚到的就绪和健康状态更新，并等待子进程输出流关闭。并发断开和释放操作合并执行。释放时关闭订阅，并禁止后续启动。监听器异常不得破坏启动或清理。

## 停止与退出

在 POSIX 上，自有子进程在独立进程组中启动。清理向已登记的组发送 TERM；宽限期结束后升级为 KILL，并在配置期限内确认子进程关闭和进程组消失。脱离该进程组的进程不在保证范围内。在 Windows 上，对仍登记且存活的自有 PID 使用 `taskkill /T`，等待关闭或明确失败。

外部连接仅断开，不向服务发送信号。不得根据端口或 URL 推断所有权。关闭最后一个可见窗口或选择退出时，等待清理完成。清理失败时保留所有权、错误和重试窗口；不得报告为空闲，也不得通过另启后端绕过失败。退出后保留持久 Home、工作区和会话。

## 信任边界

所有窗口使用 `sandbox: true`、`contextIsolation: true` 和 `nodeIntegration: false`。dsh 窗口没有 preload 或 Node 桥。只加载选定的本机回环 HTTP 源；拒绝外部导航、文件导航、新窗口和 webview。同源 fetch、WebSocket 和 dsh 工具权限询问仍由服务负责。

本地设置窗口仅加载应用文件。窄桥提供设置、状态、连接、停止、路径选择和订阅操作。主进程校验精确窗口、主 frame、文件 URL 和允许的载荷字段。拒绝未知字段和无效值。设置页拒绝浏览器权限和网络请求；dsh 页的浏览器权限仅允许同源的安全剪贴板写入。

显式地址只接受 `localhost`、`127.0.0.1` 或 `[::1]` 的 HTTP 根地址。拒绝远程主机、内嵌凭据、查询字符串和重定向。就绪地址不是回环地址时，停止自有后端并报错，不修改全局 dsh patch。

## 配置与界面

成功连接的参数保存在客户端应用数据目录。dsh 从选定的 Home 和环境中解析凭据；客户端不复制凭据。路径发现读取 PATH、常见安装路径和 realpath，不执行可能写入配置的 dsh 帮助命令。

设置窗口提供「现有服务」和「客户端启动」页签、可编辑地址和路径、路径选择器、连接操作、错误及有限长度的诊断。服务窗口直接承载 dsh UI。界面应支持键盘操作，并提供可见的焦点状态。使用系统字体、浅色背景（`#f7f9fc`）、深色正文（`#1f2a44`）、蓝色强调（`#4d6bfe`）和警告文字（`#b54708`）。页面失败与传输状态分别显示。

## 验证边界

Fixture 测试覆盖地址拒绝、就绪和健康检查、退出事实、输出读取、取消、子孙进程清理、外部服务保留、重复操作和监听器隔离。CI 中的 Linux/macOS fixture 测试和 Windows 编译，与打包应用验证及 Windows 原生清理验证分别记录。

Runtime 集成检查应使用隔离的 dsh Home，验证启动、就绪、HTTP 访问、停止、端口释放和重新打开。原生检查必须操作实际 Electron 应用、窗口控制和退出后重开。模型、工具、权限和请求取消检查需要已配置的真实服务及实际结果。明确记录未执行的检查；fixture 成功不能替代这些检查。签名、公证、自动更新和全局安装不在当前实现范围内。
